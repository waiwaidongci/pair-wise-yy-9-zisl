# 古法蓝晒底片整理室

运行：

```bash
npm start
```

访问 `http://localhost:3040`。数据保存在 `data/cyanotype-negative-room.json`。

## 药液批次台账

一缸药液可轮流用于多张玻璃板，药液单独建批次台账：

- **登记批次**：编号、类型（显影/定影/漂白液）、容量（ml）、可用起止日期。
- **补液 / 停用 / 启用**：都记录操作人和流水；补液不得超过登记容量。
- **冲洗扣量**：记录「冲洗」步骤时必须选择批次、填写本次用量和操作人，
  系统从该批次余量扣减，并同时写入批次流水和底片步骤。
- **不可用不记录**：余量不足、已过期（或未到可用日期）、已停用的批次
  会被拒绝，本次步骤不写入任何台账，接口返回具体原因。
- **双向追溯**：底片卡片的步骤历史显示每步所用批次、用量、操作人；
  批次详情（「详情/反查底片」）反查所有用过该缸的底片及完整流水。

## 代码结构（三处实现）

| 文件 | 职责 |
| --- | --- |
| `store.js` | 存取层：JSON 台账的读取、初始化、落盘，无业务判断 |
| `rules.js` | 规则层：批次登记/补液/停用、可用性判定、冲洗扣量、双向追溯 |
| `page.js` | 页面层：底片管理与批次台账两个页签的界面与接口调用 |
| `server.js` | HTTP 路由，仅做参数转发，业务规则调用 `rules.js` |

### 主要接口

- `GET/POST /api/batches` 批次列表 / 登记
- `GET /api/batches/:key` 批次详情（流水 + 反查底片）
- `POST /api/batches/:key/replenish` 补液
- `PATCH /api/batches/:key` 停用 / 启用
- `POST /api/items/:key/action` 记录工艺步骤（冲洗时传 `batchId`、`dosage`、`operator`）
